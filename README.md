# Apex shop — 계정 · 코인 상점 (자체 호스팅)

Apex 레전드 계정/코인을 무통장 입금으로 판매하는 셀프호스팅 샵입니다.
**회원 로그인 → 주문 → 자동입금확인 → 즉시 자동지급 → 내 보관함 보관** 흐름으로 동작하며,
npm 패키지 설치 없이 Node.js 내장 모듈만 사용합니다.

## 구성

| 파일 | 설명 |
| --- | --- |
| `server.js` | HTTP 서버 · 정적 파일 · 회원/관리자 API · 자동입금확인 스케줄러 · 입금 웹훅 |
| `db.js` | SQLite 스키마 · 회원/세션 · 주문/재고 · 자동지급 · Apex 샘플 상품 시드 |
| `public/index.html` | 고객 상점 (히어로 · 상품 · 디스코드 문의 · 이용안내 · 로그인/보관함 모달) |
| `public/store.js` | 로그인/회원가입 · 장바구니 · 주문 · 자동지급 폴링 · 클릭/스크롤 이펙트 |
| `public/admin.html` | 판매자 관리 페이지 (`/admin`) |
| `public/admin.js` | 현황 · 주문 · 상품 · **회원** · 후기 · 재입고 · 설정 · 자동입금/웹훅 |
| `public/styles.css` | 라이트 로즈 디자인 시스템 + 프리미엄 애니메이션/보관함 UI |
| `public/admin.css` | 관리자 전용 스타일 (자체 완결형) |
| `data/shop.db` | SQLite 데이터베이스 (첫 실행 시 자동 생성) |

## 요구 사항

- **Node.js 22.13 이상** (`node:sqlite` 내장 모듈, 24 LTS 권장)
- 기본 포트 **8080** (`PORT` 로 변경)

## 실행

```powershell
cd game-shop
node server.js
```

```
상점:    http://localhost:8080
관리자:  http://localhost:8080/admin
```

첫 실행 시 **Apex 샘플 상품 5개**(프레데터/마스터/다이아 계정, 코인, 배틀패스)가 등록됩니다.
샘플 계정 정보는 실제 판매 전에 관리자 → 상품 → 재고에서 **반드시 교체**하세요.
관리자 기본 비밀번호는 `admin1234` 이며 로그인 후 **설정 → 비밀번호 변경**에서 바꿔 주세요.

## 클라우드 배포 (Render)

`render.yaml` · `.node-version` · `package.json` 이 포함되어 있어 **Render Blueprint** 로 바로 배포할 수 있습니다.
SQLite 는 Persistent Disk(`/var/data/shop.db`)에 저장하도록 설정되어 있으며, Free 플랜은 디스크를
지원하지 않아 재배포 시 데이터가 초기화됩니다. 절차·체크리스트·문제 해결은
**[DEPLOY_RENDER.md](DEPLOY_RENDER.md)** 를 참고하세요.

무료 플랜은 15분 무요청 시 슬립되는데, 이 앱은 `RENDER_EXTERNAL_URL` 이 있으면
**5분마다 `/api/ping` 으로 자기 자신을 호출해 슬립을 막습니다**(`KEEP_ALIVE=0` 으로 해제,
`KEEP_ALIVE_INTERVAL_SECONDS` 로 간격 변경). 자세한 내용은 배포 가이드의 **2-1 절** 참고.

## 구매 흐름 (회원 계정)

1. 고객이 **회원가입**(아이디 4~20자 / 비밀번호 6자 이상) 후 로그인합니다. 이메일 입력은 없습니다.
2. 상품을 담고 **입금자명**(기본값: 닉네임)과 요청 메모를 입력해 주문합니다.
3. 주문은 `입금대기(pending)` 로 생성되고 계좌·주문번호가 안내됩니다.
4. **자동입금확인**이 켜져 있으면 설정된 지연(기본 5분, 0=즉시) 후 자동으로 입금 확인됩니다.
   실제 은행 알림을 연동하려면 관리자 → 설정의 **입금 웹훅**을 사용하세요.
5. 입금 확인과 동시에 재고가 배정되고 **즉시 지급완료(delivered)** 처리됩니다.
   (`자동지급` 을 끄면 `입금확인` 상태로만 두고 관리자가 지급완료 처리)
6. 고객은 **내 보관함**에서 아이디·비밀번호를 언제든 다시 복사할 수 있습니다.
7. 취소 시 배정된 재고는 자동 복구됩니다.

> 자동입금확인은 은행 API 없이 **시간 기반 + 웹훅**으로 동작합니다.
> 실제 운영에서는 자동확인을 끄고 웹훅(또는 수동 확인)으로 입금을 검증하는 것을 권장합니다.

## 구매 인증 후기

- **지급완료(delivered)** 주문에 포함된 상품만 후기를 작성할 수 있습니다. (회원 × 상품 1개, 중복 시 409)
- 작성 경로: 상점 **구매 인증 후기** 섹션의 `후기 작성` 버튼, 또는 **내 보관함 → 지급 완료 주문 → 후기 작성**.
- 별점 1~5 + 내용 5~300자. 작성 즉시 구매 인증(`verified`) 후기로 공개됩니다.
- 공개 목록에서는 작성자 이름이 마스킹(`홍*`)되고, 회원 ID·주문 ID 는 응답에 포함되지 않습니다.
- 본인 후기는 `DELETE /api/reviews/:id` 로 삭제할 수 있고, 관리자는 **후기** 탭에서 숨김/노출/삭제할 수 있습니다.
- 후기가 하나도 없으면 상점의 후기 섹션은 자동으로 숨겨집니다.

## 자동입금확인 · 웹훅

관리자 → 설정에서 다음을 변경할 수 있습니다.

- `자동입금확인` ON/OFF
- `자동확인 지연(분)` — 0이면 주문 즉시, 5면 5분 후 자동 확인
- `입금확인 즉시 자동지급` ON/OFF
- 웹훅 주소/토큰 (복사 버튼 제공)

```bash
curl -X POST "http://localhost:8080/api/hooks/deposit" \
  -H "Content-Type: application/json" \
  -H "x-deposit-token: <토큰>" \
  -d "{\"code\":\"GS260101-ABCD\"}"
```

`code` 대신 `amount` 를 보내면 **같은 금액의 가장 오래된 입금대기 주문**을 확인합니다.
관리자 현황의 **지금 자동확인 실행** 버튼으로 즉시 일괄 확인도 가능합니다.

### 폰 은행 알림 연동 (Tasker / MacroDroid)

은행 앱 푸시 알림을 그대로 받아 금액·입금자명을 파싱하고, 맞는 입금대기 주문을 즉시 지급합니다.
(Discord-Battle-Cat-Vending-Machine 과 동일한 방식)

1. 관리자 → **설정 → 폰 알림 자동입금확인**에서 웹훅 주소·키를 확인합니다.
2. Tasker: 프로필 → 이벤트 → 플러그인 → **AutoNotification**(또는 MacroDroid: 트리거 → 알림 → 특정 앱)로 은행 앱 알림을 감지합니다.
3. 알림 내용을 아래처럼 HTTP POST 로 전송합니다.

| 항목 | 값 |
| --- | --- |
| URL | `https://<서비스주소>/api/hooks/deposit-notify?key=<웹훅키>` |
| Method | POST |
| Body (JSON) | `{"title":"%evtprm2","body":"%evtprm3","package":"%evtprm1"}` |
| Header (선택) | `X-Webhook-Key: <웹훅키>` |

- Tasker 의 `%ntitle/%ntext` 는 알림 이벤트에서 비어 있을 수 있습니다. **`%evtprm1`(앱 이름) / `%evtprm2`(제목) / `%evtprm3`(본문)** 을 사용하세요.
- `%evtprm` 이 치환되지 않은 채 도착하면 서버는 200 + `error: "tasker_var_not_substituted"` 로 응답하고 관리자 로그에 경고를 남깁니다.
- 본문에서 **금액(`5,000원`)과 입금자명**을 파싱해 입금대기 주문과 대조합니다. 설정의 `입금자명까지 일치 확인`(`deposit_match_name`)을 켜면 금액과 이름이 모두 맞아야 확인됩니다.
- 같은 금액·이름의 주문이 2건 이상이면 **자동 지급하지 않고** `ambiguous` 로 기록합니다. (다른 사람 주문 지급 방지) 이때는 관리자 → 주문에서 직접 확인하세요.
- `입금대기 자동취소(분)`(`deposit_expire_minutes`)을 0보다 크게 두면 그 시간이 지난 입금대기 주문을 자동 취소합니다. **실제로 입금했는데 알림이 누락되면 주문이 취소될 수 있으니 주의하세요.**
- 60초 내 동일 알림은 중복 처리하지 않습니다.
- 웹훅 키는 `DEPOSIT_WEBHOOK_KEY` 환경변수 → DB 저장값 → 자동 생성 순으로 결정됩니다. 환경변수로 고정하면 DB 가 초기화되어도 유지되고, 관리자 화면의 키 회전 버튼은 비활성화됩니다.
- 관리자 → **설정 → 테스트 전송**으로 제목/본문을 넣어 파싱 결과와 매칭 결과를 바로 확인할 수 있습니다.

## 관리자 기능

- **현황**: 오늘/누적 매출, 입금 대기, 회원 수, 재고 부족, 자동입금확인 상태 카드
- **주문**: 검색(주문번호·입금자·회원 아이디) · 필터, `입금확인 → 즉시지급`, 지급완료, 취소, 되돌리기
- **상품**: 추가/수정/삭제, 노출 토글, 자동/수동 재고, 정렬, 지급 정보(재고풀) 관리
- **회원**: 아이디/닉네임 검색, 주문·결제 합계, 차단/해제, 비밀번호 재설정, 삭제
- **후기**: 회원 작성 후기 검수(숨김/노출/삭제), 관리자 직접 등록 (후기가 없으면 상점에서 섹션 자동 숨김)
- **재입고**: 회원별 알림 신청 목록, 알림완료 표시
- **설정**: 상점 이름·소개·메인 문구·공지·계좌·디스코드 링크·사업자 정보·자동화·웹훅, 비밀번호 변경

## 공개 API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/api/store` | 공개 상품 · 후기 · 설정 · 자동화 상태 |
| POST | `/api/auth/register` | 회원가입 `{ username, password, displayName? }` |
| POST | `/api/auth/login` | 로그인 `{ username, password }` |
| POST | `/api/auth/logout` | 로그아웃 |
| GET | `/api/auth/me` | 내 정보 + 주문/지급 보관함 + 후기 작성 대상 |
| POST | `/api/orders` | 주문 생성(로그인 필요) `{ buyerName, memo, agree, items }` |
| GET | `/api/orders/:code` | 내 주문 단건 조회(로그인 필요) |
| POST | `/api/reviews` | 구매 인증 후기 작성(로그인 필요) `{ productId, rating, body }` |
| DELETE | `/api/reviews/:id` | 내 후기 삭제(로그인 필요) |
| POST | `/api/restock` | 재입고 알림 신청(로그인 필요) |
| POST | `/api/hooks/deposit` | 입금 확인 웹훅(토큰 필요) |
| GET/POST | `/api/hooks/deposit-notify` | 폰 알림 자동입금 웹훅 (Tasker/MacroDroid, `key` 필요) |

관리자 API는 `/api/admin/*` 이며 `shop_admin` 세션 쿠키가 필요합니다.
회원 세션은 별도 `shop_user` 쿠키(30일)로 관리됩니다.

## 보안 · 운영 메모

- 비밀번호는 `scrypt` 로 해시되어 저장됩니다.
- 관리자/회원 세션은 `HttpOnly` + `SameSite=Lax` 쿠키입니다.
- 로그인·회원가입·관리자 로그인은 IP 기준 시도 제한이 적용됩니다.
- 요청 본문은 128KB 로 제한됩니다.
- 웹훅 토큰은 관리자 API에서만 노출되고 `/api/store` 응답에는 포함되지 않습니다.
- HTTPS 없이 운영할 경우 리버스 프록시(Nginx/Caddy) 뒤에 두세요.
- `data/shop.db` 하나에 모든 데이터가 있으니 주기적으로 백업하세요.
- 관리자 → **설정 → 데이터베이스 백업**에서 `shop.db` 를 바로 내려받을 수 있습니다
  (`GET /api/admin/backup`, 관리자 세션 필요).
- HTTPS 로 접속하면 세션 쿠키에 `Secure` 가 자동으로 붙습니다.
